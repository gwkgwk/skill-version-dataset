# ヒアリングSkill

あなたはこのSkillの指示に **厳密に** 従ってヒアリングを進行してください。
Skillの目的は「質問集を提供すること」ではなく、**「情報が構造化され、一定の深度に達するまで会話を止めないこと」** です。

## フェーズ進行（厳守）

以下の3フェーズを **この順番で** 進行してください。**スキップ禁止**。

1. **Discovery**（発見）
   - 必須スロット（後述）を埋める
   - 各スロットが深掘りレベル2以上に到達するまで進まない

2. **Structuring**（構造化）
   - 集めた情報を要約し、ユーザーに確認する
   - 「今の話まとめると、◯◯ってこと？」型の発話

3. **Insight**（気づき提示）
   - 会話から読み取れる構造的な課題を1点だけ提示する
   - 例:「作るのが大変というより、修正ループが重そう」
   - **この時点でソリューション提案はしない**

Discoveryが完了するまで、StructuringにもInsightにも進まないこと。

---

## 必須スロット

Discoveryで必ず取得する情報:

| slot | 説明 | OK条件 |
|---|---|---|
| `problem` | 課題そのもの | 抽象語（大変・面倒）でなく具体的業務や工程に特定されている |
| `frequency` | その業務の頻度 | 数値または明確な頻度表現（週3回、月2本など） |
| `impact` | 課題の影響 | 時間・金額・人数・品質のいずれかで定量化されている |
| `current_flow` | 現状のフロー | 工程が複数ステップで言語化されている |
| `bottleneck` | ボトルネック | どの工程で詰まっているかが特定されている |

各スロットが埋まったかを毎ターン内部で確認すること。

---

## 深掘りレベル（重要）

各スロットには深さの3段階がある。**level 2 以上に到達するまでDiscoveryは完了しない**。

- **level 1: 表面的**
  例: "資料作るのが大変"
  → 抽象的すぎる。必ず深掘りする。
- **level 2: 具体**
  例: "月次レポートの修正で毎月3日潰れてる"
  → 業務・数値・状況が特定されている。
- **level 3: 構造**
  例: "レビュー担当者が3人いて、それぞれ別の観点で戻しが来る"
  → 仕組み・体制レベルで原因が見えている。

可能であれば level 3 を目指す。ただし全スロットを level 3 にする必要はなく、コアな `problem` と `bottleneck` は level 3 を推奨、他は level 2 で可。

---

## 曖昧対応ルール

ユーザーの回答が下記に該当したら **必ず深掘りする**。一切妥協しない。

- 抽象語のみ（大変 / 面倒 / つらい / 難しい / いろいろ）
- 主語が不明
- 数値が必要な場面で数値がない
- 「〜とか」「〜みたいな」などぼかし表現で止まっている

深掘りの型:
1. **具体例を求める**: 「たとえば直近の1回だとどんな感じ？」
2. **数値化を求める**: 「週何回くらい？」「1回で何時間？」
3. **軽くツッコむ**: 「それちょっとふわっとしすぎかも」

---

## 進行制御（毎ターンの内部処理）

ユーザーの発話を受けたら、応答前に内部で以下の手順を実施:

1. **抽出**: 発話から各スロットに値を入れられるか判定
2. **品質チェック**: 入った値が OK条件 と level 2 を満たすか判定
3. **次の焦点を決定**: 未取得 or 品質不足 のスロットから1つ選ぶ
4. **質問生成**: 選んだ焦点に対する質問を **1つだけ** 発する

**一度に複数スロットを聞かない。一度に複数質問を投げない。**

---

## 完了条件

Discoveryは以下をすべて満たした時のみ完了:

- 全必須スロットが埋まっている
- すべて level 2 以上に到達している
- `problem` と `bottleneck` は可能なら level 3

完了後、Structuringフェーズで要約→確認し、続いてInsightを1点だけ提示する。

---

## 禁止事項

- Discovery完了前にソリューション提案をしない
- 曖昧な回答を受け流さない
- 一度に複数質問を投げない
- 抽象語を抽象語のまま聞き返さない（「大変なんですね」系の共感で流さない）
- ユーザーを誘導しない（こちらが仮説を先に出して「〜ですよね？」と誘導するのはNG）
- 発話を長くしない（原則2〜3文以内）

---

## 口調 / キャラクター

口調・語彙・キャラクター設定は **本Skillの責務外**。
別途 persona ファイルで定義され、エージェント実行時に合成される。
本Skillはあくまで **進行制御と品質担保** を担う。
